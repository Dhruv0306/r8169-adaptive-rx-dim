# Phase 1 test guide: plumbing, no behaviour change

Tests of the module built from patches 0001 and 0002 only. The `adaptive-rx` flag exists and is stored; nothing else changes. Results: [`../results/phase_1_plumbing.md`](../results/phase_1_plumbing.md). General setup: [`../setup-and-testing.md`](../setup-and-testing.md), Phase 1.

## Conditions

- Patches 0001 and 0002 applied to `/usr/src/linux-7.2.15` (after backing up the stock files to `~/r8169-stock-src/`), built with `bash scripts/build_sign_load.sh`, loaded as a signed copy. Module `srcversion` `9BF0EA4C816C5F152E47686`.
- The kernel has module signing on (`CONFIG_MODULE_SIG=y`) but does not enforce it (`CONFIG_MODULE_SIG_FORCE` is not set), so signing is optional; the build script signs a copy with the tree's key to keep the signer equal to the stock module's. The key never leaves the tree.
- Machine, peer and cautions as in the [Phase 0 guide](phase_0_environment_and_baseline.md).

## Tests

| ID | Test | Commands | Expected | Result |
|---|---|---|---|---|
| F1 | Flag round trip | `ethtool -c enp3s0 \| grep Adaptive`; `ethtool -C enp3s0 adaptive-rx on`; repeat the grep; `ethtool -C enp3s0 adaptive-rx off` | `off`, then `on`, then `off` (stock module: `n/a`) | Pass |
| F2 | Invalid combinations, and use on a chip without support | Try invalid `ethtool -C` combinations; try the flag on an RTL8125 | Rejected with an error | Not run: no RTL8125 available, invalid combinations not tried |
| F3 | Adaptive off equals stock | Compare `ethtool -c` with the stock output; `ethtool -C enp3s0 rx-usecs 50`, read back, then `rx-usecs 0`; read registers with `bash scripts/read_intrmit.sh` | Same values (`rx-usecs 0`, `rx-frames 1`, `tx-usecs 0`, `tx-frames 1`); 50 reads back as 50; registers equal to stock | Pass (completed 2026-11-11 with the Phase 0 baseline) |
| F8 | Build quality | `make M=drivers/net/ethernet/realtek modules W=1`; `perl scripts/checkpatch.pl --strict --no-tree <patch>` | No warning from `r8169_main.c`; checkpatch only the `Signed-off-by` and `Co-authored-by` items | `W=1` clean; checkpatch as expected; `sparse` not run |
| F4 to F7 | Down and up, speed change, suspend, stress | Not in scope | Moved to Phase 3 | n/a |

## What was observed

- **F1:** `Adaptive RX` read `off` after load, `on` after `adaptive-rx on`, `off` after `adaptive-rx off`.
- **F3:** registers with adaptive off read `CPlusCmd 0x2060`, `IntrMitigate 0x0000`, the same as the stock module. The Phase 0 baseline compared `stock` and `patched-off` over 140 runs and found them within about 1.3% (request-response 9213 against 9330 trans/s, 108.4 against 107.1 us, 18384 against 18627 irq/s).
- **F8:** both patches apply with `patch -p1`. 0002 showed "offset -7 lines" when tested before 0001 and applied with no offset after 0001. `modinfo -F vermagic` printed `7.2.15-netquota SMP preempt mod_unload modversions`, equal to `uname -r`.
- **After loading:** link up at 1000 Mbit/s full, no warning, oops or lockdep report in `dmesg`, gateway answered ARP and `curl` worked.

## Build, sign and load (the steps behind every test)

```bash
patch -p1 --dry-run < patches/0001-*.patch      # in /usr/src/linux-7.2.15; then patches/0002-*
patch -p1 < patches/0001-*.patch
patch -p1 < patches/0002-*.patch
make modules_prepare
make M=drivers/net/ethernet/realtek modules W=1
cp drivers/net/ethernet/realtek/r8169.ko /root/r8169-new-signed.ko
scripts/sign-file sha512 certs/signing_key.pem certs/signing_key.x509 /root/r8169-new-signed.ko
modinfo -F sig_key /root/r8169-new-signed.ko    # must equal the stock module's sig_key
rmmod r8169 && insmod /root/r8169-new-signed.ko
cat /sys/module/r8169/srcversion                 # must equal modinfo -F srcversion of the signed copy
```

`sig_key` for both the stock and the signed copy: `1B:27:B6:D0:53:DE:50:37:92:8B:C4:46:1D:75:DE:26:D9:DB:43:34` (signer `Build time autogenerated kernel key`).

## Pitfalls

- `ethtool -C ... rx-usecs 0 rx-frames 1` when those are already the values in force never reaches the driver.
- The `Adaptive RX` line reads `n/a` on the stock module and the module refuses the flag; use it to tell which module is loaded.
- `ping` shows nothing on this network (ICMP is not answered); use ARP, `curl` or TCP to judge connectivity.
- Test patches against a clean tree with `bash scripts/check_series.sh -t ~/linux-r8169-clean -c` (Phase 5) rather than only the working tree.
