# Phase 1: Plumbing, no behaviour change

Status: done (2026-11-10). The patched module was built, signed and loaded on the test machine, and the ethtool flag works. No adaptive behaviour exists yet.

Plan: [`../phases.md`](../phases.md), Phase 1.

## What was changed

Two patches against `v7.2.15`, in `patches/`. Author Dhruv Rakeshbhai Patel, with the `Co-authored-by: Claude <noreply@anthropic.com>` trailer.

| Patch | Change |
|---|---|
| 0001 | `select DIMLIB` in the `R8169` Kconfig entry. `r8169_main.c` includes `<linux/dim.h>` and `struct rtl8169_private` gets `struct dim rx_dim`, `bool rx_dim_enabled`, `u64 rx_dim_packets` and `u64 rx_dim_bytes`. Nothing uses them yet |
| 0002 | `ETHTOOL_COALESCE_USE_ADAPTIVE_RX` added to `supported_coalesce_params`. `rtl_get_coalesce()` reports the flag and `rtl_set_coalesce()` stores it as its last step. RTL8125 still returns `-EOPNOTSUPP` before reaching it |

## How it was applied, built and loaded

1. `patch -p1 --dry-run` on `/usr/src/linux-7.2.15`: both patches applied cleanly. 0002 showed "offset -7 lines" because it was tested before 0001; after 0001 it applied with no offset.
2. Applied both with `patch -p1` as root, after backing up the stock files to `~/r8169-stock-src/`.
3. `make modules_prepare`, then `make M=drivers/net/ethernet/realtek modules W=1`. `r8169_main.c` compiled with no warning or error. `modinfo -F vermagic` printed `7.2.15-netquota SMP preempt mod_unload modversions`, matching `uname -r`.
4. The kernel enforces signatures (`CONFIG_MODULE_SIG_FORCE=y`), so the build output cannot be loaded as it is. A copy was signed with the key in the tree:

   ```bash
   cp drivers/net/ethernet/realtek/r8169.ko /root/r8169-new-signed.ko
   scripts/sign-file sha512 certs/signing_key.pem certs/signing_key.x509 /root/r8169-new-signed.ko
   modinfo -F sig_key /root/r8169-new-signed.ko   # equal to the stock module's sig_key
   rmmod r8169 && insmod /root/r8169-new-signed.ko
   ```

   Signer `Build time autogenerated kernel key`, `sig_key` `1B:27:B6:D0:53:DE:50:37:92:8B:C4:46:1D:75:DE:26:D9:DB:43:34` for both the stock and the signed copy. The unsigned build output is kept unchanged. `certs/signing_key.pem` is never copied out of the tree.
5. Confirmed the running module is the new build: `/sys/module/r8169/srcversion` and `modinfo -F srcversion` of the signed copy were both `9BF0EA4C816C5F152E47686`.

After the load: the interface came back with link up at 1000 Mbit/s full, and `dmesg` showed the usual probe lines and no warning, oops or lockdep report. The gateway answered ARP and `curl` over TCP worked; see Phase 0 for why `ping` shows nothing.

## Issues met and how they were resolved

- **`git am` failed in the project repository.** The patches change kernel files, which the project repository does not contain. They are applied in the kernel tree, with `patch -p1` on the tarball tree.
- **`insmod` would have been rejected** because of `CONFIG_MODULE_SIG_FORCE=y`. Resolved by signing a copy (step 4).
- **Placeholders pasted into a shell** (`DEV=<your interface name>`) made `ethtool` fail on the first run. Rerun with `DEV=enp3s0`.
